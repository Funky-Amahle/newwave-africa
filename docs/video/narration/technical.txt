Welcome to the NewWave Africa technical walkthrough. This version demonstrates an editorial discovery interface, a story reader, a browser-local reading list, and creator planning tools. I will distinguish what the app actually does from the integrations and publishing capabilities that remain future work. The screens in this walkthrough come from the current application; the prototype's sample stories are explicitly fictional.

The application uses Next.js, React, TypeScript, Tailwind, scoped CSS modules, and Motion for interface transitions. GitHub Actions checks the code and builds a static export for GitHub Pages. The repository's base path is preserved in the deployed assets. This architecture supports a lightweight browser experience, but it does not provide an authenticated publishing backend or a persistent shared content database.

The homepage now combines a concise introduction with a manually advanced story spotlight. The reader decides when to move to the next perspective. Reusable components provide section headings, entry effects, discovery routes, and practical explanations. Reduced-motion preferences and the optional reduced-effects control help keep decorative movement subordinate to reading and navigation. Browser and assistive-technology testing remain part of release validation.

Discovery operates on local story data. Search changes the candidate collection. A selected interest changes relevance scores and result order; it is not a hard category filter. The diversity control changes the contribution of category scarcity. The implementation uses deterministic local ranking logic, not a trained recommendation model or an external artificial intelligence service. That distinction is stated directly in the interface.

The story reader uses a native modal dialog. Readers can inspect text with its category and attribution, close the dialog, and save a story to the reading list. Bookmarks store story identifiers in browser-local storage. Draft and bookmark validation helps prevent malformed restored data from breaking discovery. There are no user accounts, cross-device synchronisation, shared profiles, or public reading-list analytics in this implementation.

The insights view compares the same candidate population and the same top-eight window across its illustrative ranking approaches. Expanding the visible feed does not change that comparison window. Category counts remain available as text alongside the bars. This makes the prototype more inspectable, but these metrics still do not establish real audience outcomes, recommendation quality, or fair representation at scale.

Story narration now uses recorded audio only. A shared manifest loader accepts each fixed sample's own MP3 filename and supports the GitHub Pages base path. Playback ownership coordinates a single active story. The controls support pause, resume, stop, and cleanup when a card disappears. Missing or failed audio remains silent and readable; the app no longer calls browser speech synthesis or displays a system-voice selector.

The Deepgram generation pipeline is separate from that browser playback path. A manual Actions job reads fixed fictional repository samples and uses a server-side Actions secret. It prevalidates selected stories, bounds responses, checks manifest associations and MPEG structure, and uploads a temporary review artifact. Generation does not publish audio. Decoding, pronunciation, content matching, and human review are still required before an explicitly approved publication change.

Creator Studio contains five human-led planning canvases. Their fields support creative structure, context, attribution, accessibility, and permissions across different disciplines. The brief export is editable Markdown. Toolkit notes are temporary page state unless downloaded. The story form separately supports a live preview, local categorisation rules, a rights confirmation, and browser-local draft storage. None of those actions demonstrates a hosted public submission service.

The microphone recorder uses browser media APIs after the person requests recording and grants permission. It offers a local preview and download. It does not automatically send a recording to Deepgram or attach it to a published story. A successful build cannot prove microphone sound quality, device compatibility, or consent usability; those need actual browser and device checks with non-sensitive test material.

Validation combines TypeScript, static builds, and focused tests for discovery, brand assets, narration contracts, and playback behaviour. Simulated media tests are useful for state transitions, but they are not listening tests. A deployment should be checked against its exact source revision and Pages result. This walkthrough likewise separates rendered interface evidence, automated checks, and capabilities that have not been independently verified.

The roadmap includes creator-controlled publishing, protected backend services, opt-in transcription, captions, language support, and evaluation with real creators. Those features should be developed with explicit consent, input limits, retention rules, and rights review. NewWave Africa's technical aim is to extend creative craft while making system boundaries understandable. The current prototype is a foundation for that work, not a claim that the whole platform is finished.
